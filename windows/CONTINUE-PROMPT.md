# 可直接复制的 Windows 接续开发提示

将下方内容复制到 Windows 上的开发助手，工作目录选择本仓库根目录。

```text
请在当前 ScreenBridge 仓库开发映桥的 Windows 原生版本，直接完成代码、测试和可安装产物，不要只写方案。

先检查 git status 和本地规则，阅读 windows/DEVELOPMENT.md、windows/README.md、macos/docs/hardware-compatibility.md；若 windows/ 已有后续实现，先检查再继续，不要覆盖或重新初始化。所有实现放入 windows/，保留 macos/、MIT 许可和上游署名。

目标 Windows 11 x64，建议 C# + .NET 10 LTS + WPF。先确认本机 SDK，创建可维护的工程、PowerShell 构建/测试/打包脚本，再分步实现：
1. 原生显示器枚举、稳定身份、DDC 通道及后台操作队列。
2. 仅硬件亮度控制，禁止 Gamma 或遮罩软件调暗。
3. 按每屏实际接线配置本机接口和切换目标，提供切到目标/返回本机；支持 DP、HDMI、USB-C、自定义名称与写入值。未配置不猜测，当前读回仅作参考，不能自动当成本机接口或写入值。保存不切屏，原始数字不转换。
4. 托盘面板、“全部切到目标”“全部返回本机”、真实状态的登录启动，以及顶层“排列显示器”系统设置入口。
5. 热插拔、休眠恢复、句柄释放、阻塞恢复与诊断日志。

重要映射：macOS 实测 JU24 DP1 写18/读15，DP2 写15/读16；JU27 DP1 写18/读15，DP2 未验证，不擅自认定为15。G73 写7/8，G4Q 写15/16且旧 macOS 扩展坞接法存在返回限制。匹配厂商+产品；这些都不能标成 Windows 已验证。具体标识和证据以 DEVELOPMENT.md 为准。

不要把 DDC API 返回成功、读回失败或短暂读回目标当成画面切换成功。自动化测试使用模拟硬件，不自动切走当前工作屏；真实切屏按用户明确授权逐项进行并确认画面。不要盲扫寄存器、恢复出厂或写固件。

按 DEVELOPMENT.md 的验收清单完成自动化和 Windows 实机验证。交付源码、中文使用说明、测试结果、x64 便携 ZIP、安装包与校验值。缺少硬件、SDK或签名条件时，继续完成不依赖该条件的部分，明确哪些验证未执行；不要虚构 Windows 构建或硬件测试已通过。

开始实施前用简短中文说明当前仓库状态和第一步，随后直接开发。
```
