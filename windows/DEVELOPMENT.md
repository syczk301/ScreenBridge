# Windows 开发说明与接续任务

更新时间：2026-11-14。当前 Windows 目录只有开发说明，尚无实现、工程文件或安装包。本文是开发规格，不是已完成功能清单。

## 1. 开发目标与范围

开发原生 Windows 显示器控制应用 **映桥 ScreenBridge**，与本仓库 macOS 版保持核心交互一致：系统托盘、硬件亮度、按实际接线切换/返回、每屏自定义接口数值、批量切到目标/返回本机、开机启动。

首版目标为 Windows 11 x64，简体中文界面。交付完整源码、测试、构建脚本、便携包和安装包。Windows ARM64、Windows 10、夜览、深色模式联动和复杂显示器排列编辑器不作为首版承诺。

所有 Windows 实现放入 `windows/`。不移植 macOS 私有 API，不修改已发布 macOS 行为，不覆盖已有 macOS Release 附件。保留仓库 MIT 许可及上游署名；复制或改写上游代码时保留对应来源说明。

## 2. 开发环境与目录建议

建议采用 **C# + .NET 10 LTS + WPF**，UI 使用 MVVM；选择少量维护成熟的依赖并说明用途。项目目标可用 `net10.0-windows`。开始实现时核对 SDK 支持状态，并通过 `global.json` 固定团队实际使用的 SDK；不在本文预设未核验的 SDK 补丁版本。

截至本文更新日期，.NET 10 是受支持 LTS；.NET 8/9 即将结束支持，不建议新项目默认从 .NET 8 开始。依据见 [官方支持策略](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core) 和 [.NET 8/9 支持结束公告](https://devblogs.microsoft.com/dotnet/dotnet-8-9-end-of-support/)。

在 Windows 安装 Git、.NET 10 SDK；可以使用支持该 SDK 的 Visual Studio 或其他编辑器。首次接续：

```powershell
git clone https://github.com/syczk301/ScreenBridge.git
cd ScreenBridge
git switch -c feat/windows-initial
Get-Content windows/DEVELOPMENT.md -Encoding utf8
dotnet --info
```

如果已有克隆，先检查 `git status`，保留未提交修改，再更新远端；不要用强制重置覆盖其他平台工作。

建议布局（以下项目和脚本均需开发者创建）：

框架层不应引用 WPF。原生 DDC 层通过接口注入，模拟测试不访问真实显示器。构建脚本应支持从任意工作目录调用，生成文件不提交 Git。

## 3. 显示器识别与通道绑定

自动枚举所有物理外接显示器，显示型号、分辨率、刷新率和连接状态。排除虚拟显示器；不能把内置屏幕误绑定到外接 DDC 通道。

使用 EDID 厂商/产品/序列号、设备路径、连接信息建立设备身份。运行时 HMONITOR、物理句柄、列表顺序不能作为持久配置主键。EDID 序列号可能缺失或重复，必须考虑两台相同型号；无法可靠匹配时不静默合并配置、不写错设备。

接口方向：

- `EnumDisplayMonitors` / `GetMonitorInfo`：枚举逻辑显示器。
- `GetNumberOfPhysicalMonitorsFromHMONITOR` / `GetPhysicalMonitorsFromHMONITOR`：建立物理句柄集合。
- `GetDisplayConfigBufferSizes`、`QueryDisplayConfig`、`DisplayConfigGetDeviceInfo`：获取当前路径、显示器名称及源/目标信息。
- 结合设备接口和 EDID 核验身份；不要仅凭显示名称或数组索引连接两套枚举结果。

一个逻辑显示器可能对应多个物理显示器，不能只取第一个句柄。拓扑变化后重建对应关系，旧句柄失效时废弃旧请求；为每次枚举设置代次，防止过期结果更新新设备。配置迁移需保守处理同型号不同设备。

刷新率区分固定模式和 VRR。无法获得可靠 VRR 范围时显示当前模式频率或“范围未知”，不得把最大频率伪装成实际瞬时频率。

## 4. DDC 通信实现

优先使用 Windows Monitor Configuration API（Dxva2）：

- `GetVCPFeatureAndVCPFeatureReply`
- `SetVCPFeature`
- `GetCapabilitiesStringLength` / `CapabilitiesRequestAndCapabilitiesReply`
- `DestroyPhysicalMonitors`，或与单句柄所有权对应的释放机制。

所有成功获得的句柄都必须释放，避免重复释放；读写未完成时不能释放其句柄。声明 P/Invoke 时核对结构体布局、字符集、布尔返回值、错误码与资源所有权。

DDC 不得阻塞 UI。每屏串行化通信，不同屏可独立执行；能力字符串读取与亮度轮询也必须经过同一协调机制。设置有限重试和退避，不用持续重发切屏命令掩盖失败。

原生调用可能长时间阻塞。`Task.Run` 加超时等待或取消令牌不会终止已进入的原生调用：必须限制挂起任务数量，并避免超时后继续在同一通道启动无限任务。若需要可靠强制恢复，可使用受控辅助进程隔离原生调用；明确说明策略和未覆盖的限制。

热插拔、休眠恢复、驱动重置后重新枚举，回收失效通道。首版不要求移植 macOS 的 HP G2 MST 私有底层通道；先验证 Windows 标准 API 的能力。

官方参考：

- [低层显示器配置 API 使用流程](https://learn.microsoft.com/en-us/windows/win32/monitor/using-the-low-level-monitor-configuration-functions)
- [QueryDisplayConfig](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-querydisplayconfig)

## 5. 硬件亮度

通过 VCP `0x10` 读取与写入硬件亮度。有效读数应校验最大值和当前值，转换为 0–100% 硬件标尺；非 100 的硬件范围也要正确换算和四舍五入。

**禁止软件调暗**：不得以 Gamma、透明遮罩、改变颜色或对比度替代硬件背光。不能调节时明确显示不可用或失败，不假装写入成功。亮度、夜览和深色模式不要合并。

滑块请求合并，优先提交最新值；写入中或正在拖动时，旧轮询读数不能覆盖当前操作。写完在合理延迟后读取实际值并更新界面。测试失败时保留真实状态，不把缓存当作实时硬件读数。

## 6. 输入源交互与命令语义

每屏先按实际接线明确配置“本机接口”和“切换目标”，界面提供“切到目标”和“返回本机”。本机接口指显示器一端连接当前电脑的物理插口，不固定为 DP2；目标也不固定为 DP1。支持 DP、HDMI、USB-C 和自定义名称。

本机/目标各自保存名称、最终写入值及可选预期读回值，两个角色不能相同。接线配置按稳定设备身份保存；换线后用户需重新确认，不能仅凭型号推断电脑接在哪个口。读取当前输入仅供参考，可能正在显示另一台电脑，不能自动覆盖本机接口；读回值也不能直接作为写入值。

未配置时提示设置接线，不猜测目标或返回接口。保存配置不发命令；用户确认前不把系统连接类型（如 DisplayPort）推断成显示器上的 DP1/DP2。具名预填仍采用自定义→精确型号→标准候选，保存后的接线配置使用最终数值快照。更改其他自定义列表不应静默更改接线角色。

点击即发送 VCP `0x60`，不依赖先读当前输入，重复点击同一目标仍可发送。不通过禁用显示设备、断开屏幕或改变显示拓扑模拟输入切换。

每屏允许自定义十进制或十六进制写入值。与 macOS 配置一致，允许范围 1–65535；校验空值、越界和歧义名称，保存配置不应立即切屏。命名目标的优先级为：用户自定义 → 精确匹配的型号配置 → 标准候选值。显式数值必须原样发送，不再套用型号映射。

模型需要把以下字段分开：目标名称、写入值、预期读回值、验证平台及证据。数值 18 在标准表里叫 HDMI2，但对于已实测 JU24/JU27，它是 DP1 写入命令，不能仅按标准名称重命名 UI。

“发送成功”仅表示底层调用成功；读回不可用不等于切换成功。切屏后等待数秒，再区分匹配、未匹配、不可读和短暂匹配后回切。首次验证仍需用户确认物理画面。验证失败不能触发无限自动重发或把输入切回原电脑。

### 批量切换与返回

在面板下方提供“全部切到目标”和“全部返回本机”，风格与其他菜单行一致。分别按各屏已确认的接线配置发送，不固定任何接口或型号；未配置的屏幕跳过并报告。开始前保存目标及身份快照，独立发起每台命令；其中一台失败或切走不能阻止其余目标。运行中禁止重复点击，最终显示逐屏发送结果。

不承诺切到其他设备后一定能从非当前接口切回来。

## 7. 型号映射与证据

下表源于 macOS 实测，可作为 Windows 待验证配置；不能标成 Windows 已验证。

| 型号 | EDID 厂商 | EDID 产品 | DP1 写入 | DP2 写入 | 已知读回 |
|---|---:|---:|---:|---:|---|
| JU24F160L | 21063 | 9237 | 18 / 0x12 | 15 / 0x0F | DP1=15，DP2=16 |
| JU27F160L | 21063 | 10000 | 18 / 0x12 | 未验证；标准候选 16 | DP1=15，DP2=16 |
| G73 | 19491 | 10083 | 7 / 0x07 | 8 / 0x08 | DP2 曾读回 8 |
| G4Q | 19491 | 9571 | 15 / 0x0F | 16 / 0x10，原接法存在返回限制 | DP2=16 |

- JU24/JU27 声明 `60(0F 10 11 12)`，但实际 DP1 写入 18。不能把能力字符串当成最终答案。
- JU24 写 18 后曾短暂回切，之后重发并由用户确认保持 DP1；原因未确定。写 15 后用户确认 DP2。
- JU27 写 18 后在 10 秒、20 秒读回 15，用户确认稳定。**JU27 DP2 未实测，不能直接改成 15 并宣称成功。**
- G73 的 7/8 已双向实测，不要覆盖成标准 15/16。
- G4Q 在 macOS＋惠普 G2 DP 链路能切到 DP1，但从非当前 DP2 接口不能切回来。这不证明 Windows 也有同样限制。
- JU24 已确认 Mac 直连；不要沿用旧 G73/G4Q 的扩展坞拓扑推断新设备。
- EDID 厂商数值应按 EDID 格式和字节序核对，不能直接拿 Windows 的另一种厂商标识比较。必须同时限定厂商和产品；匹配失败保留标准候选或用户自定义。

具体证据及 macOS 限制见 [硬件兼容记录](../macos/docs/hardware-compatibility.md)。

## 8. 托盘、配置与诊断

托盘使用简洁的显示器图标；点击打开中文控制面板，关闭面板不退出应用，菜单提供明确退出项。默认日常运行不需要管理员权限。

提供“开机启动”开关，显示真实注册状态；失败不能保持虚假的已开启状态。卸载时清理该应用创建的启动项。“排列显示器”作为顶层入口，首版可打开 Windows 系统显示设置。

支持单实例运行。配置存放在适当的用户数据目录，原子写入，带版本号，损坏时提供恢复路径。保存映射不能顺便发硬件命令。

日志记录时间、操作、目标匿名标识、VCP、写入值、读回值、耗时及错误。导出时避免包含账号、完整机器路径、未经处理的设备序列号等个人信息；不把日志或用户配置提交仓库。

输入值探测只在用户主动启动后逐项执行，明确目标屏幕、间隔和停止条件；读回匹配或失联后暂停等待确认。禁止自动扫描所有 VCP 寄存器，不发送恢复出厂、固件写入或未经授权的电源控制。

## 9. 测试与验收

### 自动化测试（模拟硬件）

- [ ] JU24 DP1→18、DP2→15；JU27 DP1→18，DP2 标记未验证。
- [ ] G73 7/8 与 G4Q 15/16 不受新型号影响；厂商或产品不匹配时不套用配置。
- [ ] 自定义优先；显式原始数值不转换；保存配置不发命令。
- [ ] 未知当前输入仍能写入，同一目标可重发。
- [ ] 批量去重、排除内置/虚拟屏、单屏/空列表、某屏失败其他仍执行。
- [ ] 混合接线：一台本机 DP2/目标 DP1，另一台本机 HDMI1/目标 USB-C，切换与返回各用正确数值。
- [ ] 未配置不写入；保存接线不切屏；相同角色/数值被拒绝；清除配置后不回退猜测 DP1/DP2。
- [ ] 当前输入读回不会覆盖本机接线，配置持久化及重新接线后的更新准确。
- [ ] 亮度 20/100 显示 20%；非 100 范围正确换算，非法范围被拒绝。
- [ ] 无软件调暗路径；过期读数、过期设备代次不能覆盖新状态。
- [ ] 超时不无限创建后台请求；句柄异常路径也正确释放。
- [ ] 配置持久化、损坏恢复及启动项失败状态准确。

### Windows 实机验收

- [ ] Windows 11 x64 编译运行，托盘和高 DPI 界面正常。
- [ ] 普通用户可操作；热插拔、休眠恢复后不控制错屏。
- [ ] 每台显示器分别测试 DP1、DP2，记录写入与读回并确认实际画面。
- [ ] 切换后等待足够时间，确认没有自动回切；记录非当前接口是否仍可控制。
- [ ] 亮度改变真实背光，图像没有软件调暗引起的发灰或对比度变化。
- [ ] 双屏按各自配置切换及返回时，第一台切走不会阻断第二台；失联时明确显示不可控。
- [ ] 安装、升级、卸载、登录启动和便携启动通过验证。

在 `windows/docs/hardware-validation.md` 记录 OS、显卡/驱动、型号/固件、连接方式、DDC/CI 状态、测试时间和结果。未执行项目保持未验证，不勾选完成。CI/模拟测试不等于真实屏幕验证。

## 10. 实施顺序与交付

1. 创建工程与测试，完成设备枚举和只读诊断。
2. 实现 DDC 服务、型号映射及单屏亮度/输入切换。
3. 实现托盘、批量切换、自定义配置、启动项与系统设置入口。
4. 完成热插拔/休眠/阻塞恢复，执行 Windows 实机验收。
5. 提供 PowerShell 构建与打包脚本、便携 ZIP、安装包及 SHA-256 校验。

未来工程创建后，至少提供等价于 `dotnet restore`、`dotnet build -c Release`、`dotnet test -c Release` 和面向 `win-x64` 的发布流程。当前仓库尚无 Windows 工程，这些命令现在不能作为已可运行的构建说明。
